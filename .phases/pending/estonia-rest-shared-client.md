Prerequisite for the three Estonia REST tickets (index-miss fallback, full-history people, a legal person's companies), from the REST API evaluation of 17 Oct 2026. RIK's contract gives OpenCheck's contract partner one simultaneous query and 50,000 answers a day, shared by the REST key and the SOAP credentials and by every user. New `sources/ariregister_rest.py`: one `asyncio.Lock` per event loop held for the length of a request (the `ny_dos` rule), shared with `fetch_timeline_data`'s two SOAP calls through `contract_slot`; a caller that waits past `ARIREGISTER_QUEUE_WAIT_S` (20 s) is refused as busy. A daily budget charged per request sent on the register's Tallinn day, `ARIREGISTER_DAILY_BUDGET` (40,000 by default, capped at 50,000; in memory, so a deploy restarts it — hence the headroom). The REST token from `GET /keyLogin/` with the key in the `apiKey` header, cached per process and fetched again on a 401; every call sends `acceptLanguage: eng`, `apiVersion: V1` and the shared User-Agent. Outcomes: `RikNotFound` only for RIK's 404 `code: 4043`; `RikUnavailable` for a spent budget, a busy slot, a refused key (an unknown key is a 404 `API Key not found`, read as refused), 403, 422, 429, 5xx, timeouts and unreadable bodies, with a degradation reason and a fixed sentence; `RikNotConfigured` without a key, so every caller falls back as before. The client caches nothing (Phase 262). SOAP failures now say why: `fetch_timeline_data` returns `unavailable` causes and `read_history` words a busy slot or spent allowance as `rate_limited` with the client's sentence, and the finding still says "ownership history not read". `/signalstats` gains `ariregister_rik` — requests today, remaining budget, outcomes by `service|outcome`, refusals and the queue, closed vocabularies only. `personal_data_paths` is the check a REST-built bundle must pass (person codes, e-mail; exact personal-code values under code keys). Fixtures are real answers read with the live key on 17 Oct 2026, token replaced. Production check: `/signalstats` → `ariregister_rik.rest_configured` true and `soap_configured` true; open an Estonian company's History tab and confirm `soap_detail|answered` and `soap_beneficial_owners|answered` count up.
