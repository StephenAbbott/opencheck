---
title: The monthly BODS series can be previewed between editions.
readme: The monthly BODS series workflow gained a preview mode that builds, without publishing, what the next edition would say today.
tests: backend +3
---
The first edition of the series (`bods-series-2026-11`) is every record as `new`; change over time only shows from the second edition, on 2 December. For the demos on the "Demonstrating change over time" ticket Stephen chose (17 Nov 2026) to preview the diff now rather than wait. `publish-bods-series.yml` takes a `preview` input on a manual run: `build_bods_series.py --refresh-mirror --edition <today>` brings the downloaded mirror up to GLEIF's latest Golden Copy publish with the smallest delta that covers the gap, builds a full edition against the last published ledger (so closures are computed, unlike a `limit` trial), and keeps `out/` as the artifact `bods-series-preview` for thirty days. Nothing is published and the ledger the preview wrote is not uploaded, so December's edition is still compared with November's. `--refresh-mirror` is refused without `--edition`. The delta logic moved from `sweep_estonia.refresh_mirror` into `mirror_refresh.refresh_to_latest` (raises `MirrorNotRefreshable`), which both scripts now call. It runs on a GitHub runner because GLEIF's file storage answers 403 to the cloud environment the build was first tried in. After merge: run the workflow once with preview ticked and read the artifact's manifest counts.
