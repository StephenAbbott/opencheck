Found while validating PR #494 locally: one commit gave 40, 31 and 25 failures on one machine depending on what sat in data/ — the local Estonian index answered where the tests mock the print page, a stale meip.sqlite failed two MEIP tests, and with the data root emptied the tracked curated bundles went too. CI, which checks out tracked files only, saw the third. tests/_data_root.py, installed at conftest import beside the network guard, points OPENCHECK_DATA_ROOT at a per-session temporary tree seeded from the tracked data/ files (real directories, one symlink per tracked file from git ls-files, a fixed subtree list when git cannot answer), so the curated bundles resolve and anything a test writes — the live response cache, dispositions — stays in the temporary tree; a developer's own OPENCHECK_DATA_ROOT is overridden. It also removes asset paths exported in the shell: every Settings alias ending _FILE, _DB or _DIR and the five *_INDEX_PATH overrides the bulk adapters read directly. Stephen's decisions (28 Oct 2026): seed from the tracked tree, symlink rather than copy, and an opt-out marker — @pytest.mark.local_data("meip.sqlite", …) runs a test against the developer's real data root when every named asset is present and skips it otherwise; test_meip's two real-register tests take it and now read data_root() instead of a path built from __file__. test_dataless_suite.py pins the seeded root, the curated bundles resolving through it, no release asset visible, the Estonian index tier unreachable by default, writes never reaching the checkout, the removed environment variables (and fails on a new os.environ asset path the list does not name), the fallback list covering every tracked file, and both directions of the marker. CLAUDE.md's test-suite section says the suite is offline and dataless. Nothing in the application changed.
