From the codebase review of 20 Nov 2026. `tests/test_adapter_failure_paths.py` calls each registered adapter's probe read path (`sources/probes.py`) with every request answered 503, then with every request timing out. It accepts three outcomes: the adapter raises, it returns a stub with a `source_fetch` degradation, or it returns a card with a degradation. Whatever the outcome, nothing may be written to the response cache (Phase 262), and the failure's text may not reach the bundle. 45 adapters are graded; the floor is 35. A source whose credential or store is absent is not graded, and a 404 stays each adapter's own test. Seven adapters fail today and are pinned by id in `KNOWN_GAPS`, each with what it does: `ariregister` with no index, `cnpj_brazil` (also caches the empty card), `cro`, `malta_mbr`, `mca_india`, `prh` and `wikidata`. An entry that starts passing fails `test_known_gaps_are_still_gaps`, so the list only shrinks. The test found an eighth case, fixed here: `eiti_soe` cached an empty payments list after a failed read, so the SOE read "no payments" until the entry expired. It now caches only an answer. KRS, ABR and Firmenbuch are fixed by the KRS/ABR/Firmenbuch degradation PR, which this branch includes.
