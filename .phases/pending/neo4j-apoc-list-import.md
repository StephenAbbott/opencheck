---
title: The demo Neo4j import scripts load list properties as lists, through APOC.
readme: The demo graph's Neo4j import scripts now load source types, nationalities and alternate names as native lists, so the CSV import round-trips back to BODS exactly as a direct load does.
---
Regenerated `import.cypher` and `import.sh` in `data/demo/neo4j/` and the `import.cypher` inside all twelve per-LEI zips with bods-neo4j `1775533` (issue StephenAbbott/bods-neo4j#4). Until now the CSV route stored every list property as a JSON string, so `to-bods` on a graph loaded from these files dropped `source.type` on every statement and person nationalities. The script now parses each JSON-list column with `apoc.convert.fromJsonList()` and checks for APOC before loading anything, so **loading the demo files needs APOC Core** (Neo4j 5 ships it as `labs/apoc-*-core.jar`; bods-neo4j's docker-compose enables it) and Neo4j's default `db.import.csv.legacy_quote_escaping=true`, which the CSVs are now written for. Every CSV is byte-for-byte unchanged: the demo data has no cell with a backslash, the only cells the new quoting touches. The nine bulk zips and the root files were rebuilt from `data/demo/*.jsonl` by `export_neo4j.py`'s own steps; the three live-export zips (Eesti Energia, Ørsted, Eli Lilly) are dated snapshots with no BODS file in the repo, so their CSVs were rewritten in place by a conversion checked first against the ten rebuildable exports, where it reproduced a fresh export byte for byte; their `LICENCES.md` is unchanged. Verified on Neo4j 5.26 + APOC 5.26 with default settings: the demo graph loads 520 entities / 18 persons / 666 relationship statements, `sourceTypes`, `nationalityCodes` and `alternateNames` load as `LIST<STRING>` from every zip, `to-bods` returns the same 1,204 statements from the CSV-loaded graph as from a direct load, and `demo_queries.cypher` returns its stated numbers. `export_neo4j.py`'s instructions and `docs/datasets.md` say APOC is needed. The Estonia dataset release's Neo4j zip was rebuilt the same way (a release-asset swap; `data/estonia/` is not in git). Check in production: nothing — no runtime code changed.
