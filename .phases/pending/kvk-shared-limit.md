KvK replied on 17 Nov 2026 to the questions of 27 Oct. The 429s on requests paced at one a minute come from the second limit, 200 requests every five minutes shared by every KvK user, and KvK raises neither limit for anyone. A bulk file with the KvK number will not come: article 2(1)(h) of the Wet hergebruik van overheidsinformatie keeps personal data in public registers out of re-use, following the Autoriteit Persoonsgegevens' advice, so KvK keeps anything that could be personal out of the High-Value Dataset. A KvK 429 now reads as the shared limit being reached, with "Try again in a few minutes"; a request the throttle holds back after one says the same and "not sent" (`HostRateLimitedError.after_refusal`); only a request held back by this server's own minute says "one request a minute from each address". Still a `rate_limited` degradation and the "Did not answer … Try again" card, as decided on 27 Oct. A 404 is remembered through `put_absent` (same entry, now said). The 404 coverage note names the law. `kvk` joins `knowability.RECORD_ONLY_SOURCES`, so the Netherlands statement says OpenCheck reads the register record only, no officers or owners, instead of "officers and registered holdings", which the open data never held; `docs/knowability.md` regenerated. `docs/sources.md` corrects the KvK row (it said "authorised representatives") and adds a section on what the open data can and cannot carry and why. After deploy: look up ASML, then Heineken within a minute; the second card should say this server's minute was used, not the shared limit.
