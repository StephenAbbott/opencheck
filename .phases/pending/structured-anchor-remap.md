title: FullCheck's anchor collapse rewrites reference fields, never text — the structured id remap.
readme: FullCheck's anchor collapse now rewrites only the fields that reference a party, leaving annotation sentences and summaries as written.

Follow-up to the content-addressed statementId phase (Notion "Structured id remap for the FullCheck anchor collapse"). `routers/expand.py::_apply_id_remap` collapsed every representation of a hopped company onto the existing graph node by serialising the hop's BODS and risk signals to JSON and string-replacing the collapsed ids — every occurrence, an annotation sentence, an interest's `details` or a signal's `summary` included, with no idea which fields are references. It is now a walk of the reference fields `bods/refs.py` names: `remap_statement_references` rewrites `statementId`, `recordId`, `declarationSubject`, `recordDetails.subject` / `interestedParty` (bare or legacy `describedBy*` wrapper, written back in the same shape; an `UnspecifiedRecord` untouched) and `componentRecords` (`STATEMENT_REFERENCE_FIELDS`); `remap_signal_references` rewrites the `SIGNAL_REFERENCE_FIELDS` the Phase 398 resolver names **and** any `statement_id` key or key ending `statement_ids` at any depth of `evidence` (Stephen, 24 Oct 2026: both) — the blunt replace had silently covered `STATE_CONTROLLED`'s `state_holdings[].parties[]`, `TRUST_OR_ARRANGEMENT`'s `elements[].statement_ids` and `relationship_statement_ids`, which the named list does not reach. Both copy on change and read no other string. `_anchor_replacements` is unchanged: both ids of each subject statement are still rewritten to the anchor's statementId (Stephen, 24 Oct 2026 — the resolver takes a statementId reference at tier 1, and the collapsed statement is dropped on the canvas as a duplicate of the anchor's; passing the anchor's recordId through the three request shapes was considered and not done). `tests/test_expand_structured_remap.py` scrambles a hop into the MEIP shape (statementId ≠ recordId on every statement, `declarationSubject` naming the head, a wrapped reference, an `UnspecifiedRecord`), checks the collapsed graph draws one node for the company, that free text carrying the old id survives byte-identical, that nested evidence is reached, and pins both field lists so a reference field added elsewhere without a name here fails. No frontend change; the `bodsRefs.ts` parity test is unaffected (the tiers did not move). Nothing to check in production beyond a FullCheck expansion drawing as before.
