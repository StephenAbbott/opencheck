Found while settling the KvK follow-up ticket (27 Oct 2026). Since Phase 324 an adapter that cannot reach its upstream records a `source_fetch` degradation and returns a stub rather than raising, and Phase 412 made KvK's rate limit one of those. The pipeline then emitted `source_completed` with no results and no `source_error`, so the report contradicted itself: the degraded-sources notice and the verdict said KvK had been rate-limited, while the source list put KvK under "Answered with no record", coverage counted it as answered, and there was no card — so no Try again button, which only renders on a card with an error. The same was true of every adapter that degrades this way.

`_source_outcome`, the one reading of a dispatched source shared by the run and `/lookup-source` (Phase 331), now asks `degradation.unanswered_fetch(source_id)` when a source produced nothing and no stored Open Ownership bundle stands in. A recorded `source_fetch` failure becomes the source's error, worded by the adapter's own sentence (which carries no entity name, the degradation rule), with `error_type` `timeout` for a timeout and `fetch_error` otherwise. The source then gets the existing "Did not answer — …" card with Try again, the loading grid counts it as failed, and coverage, the MCP summary and the batch row count it as not answering. `add_source_errors` does not repeat it: the adapter's own degradation already covers the source. `/lookup-source` opens its own degradation scope so a retry reads the same way. Two cases are deliberately left alone: a source that answered with a card and noted a problem (a note card, a partial read), and a `not_configured` degradation — a missing credential is a fact about the deployment, and a retry changes nothing. No frontend change: the card, the retry and the failed count already read `source_error`.

To check in production: look up a Dutch company twice within a minute (ASML `724500Y6DUVHQD6OXN27`, then Heineken `724500K5PTPSST86UQ23`). The second KvK card should read "Did not answer — KvK open data allows one request a minute from this server…" with Try again, and KvK should not appear under "Answered with no record". Trying again after a minute should bring the record.
