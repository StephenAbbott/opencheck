Every one of RIK's daily open-data files holds current rows only, so the ownership graph never drew a former owner of an Estonian company, although Phase 317 emits ended ownership everywhere OpenCheck has it. The history is in the credentialed X-Road service the Time Machine already reads (`detailandmed_v2` and `tegelikudKasusaajad_v2` with `ainult_kehtivad=0`). Read on 16 Oct 2026 with the production envelopes: Bolt Technology OÜ's card history holds 460 ended shareholder rows from 164 holders (84 still hold shares; 387 rows are a holding re-registered when its size changed) and five ended beneficial-owner entries; Eesti Energia AS 13 ended AS-shareholder rows and 31 ended BO entries. The rows have the bulk rows' shape, so the existing shareholding builder maps them unchanged, and every current row's `kirje_id` is the bulk row's (Bolt 183/183, Eesti Energia 11/11 BOs) — which is how the personal code a SOAP row carries, in place of the files' `isikukood_hash`, joins an ended holding to the same person's current node exactly, with no name matching. `sources/ariregister_history.py` keeps ended shareholder (`O`, `S`, `OSAN`) and BO rows, joins them, groups a former-only person's rows by code under a `hist-<first kirje_id>` key, joins code-less rows on name and birth date where the index gives one, and drops every natural person's code — Estonian and foreign (a Lithuanian asmens kodas is 11 digits too) — before anything leaves; nothing derived from a code is published, since a hash of one is reversible by enumeration. The schema refuses either kind of code on a natural person. Stephen's decisions (16 Oct 2026): one closed relationship per party per company with each register row an interest (Bolt about 164 records, not 460); a current holder's earlier holdings as a separate closed record the graph pools with the current one; read on every Estonian lookup, a successful (stripped) read cached per registry code for a day. History statements are dated by the register's last end date, not the files' cut. Index tier and the subject only — the page fallback already lists its ended holdings and has no `kirje_id`. Offline instances read nothing; no credentials or a failure records a `source_read` degradation and the finding says "ownership history not read"; a failure or a missing BO history is never cached. Provenance stays the dated snapshot; integrated figures are unchanged (former holders are listed as formerly, without a figure). The History tab now says what the Estonian change log covers, without the 1 Sept 2023 "boundary" the ticket proposed: that is when the card's own shareholder role began, and Bolt's off-card history starts in 2013. Part 2 of the ticket (the `registrikaardid` file as a card-entry event spine) is a follow-up; the SOAP card log is already parsed. After deploy: open Bolt Technology OÜ (FullCheck) — former shareholders drawn faint with their end dates, current ones unchanged — and check Eesti Energia's card; former BOs (former board members) are now screened as former related parties. Notion: Estonia: full history — ended shareholdings and owners from the SOAP history into the graph.
