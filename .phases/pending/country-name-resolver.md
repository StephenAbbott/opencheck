title: One resolver reads a country name, so a Russian or Turkish party filed by name now carries its ISO code.
readme: Every country-name helper now shares one resolver, so "Russia", "Turkey" and other names pycountry no longer knows get their ISO code and reach the FATF, EU high-risk, non-EU and tax-list checks.
tests: backend +47
---
`bods/statements.py` had two free-text country resolvers with two alias tables, and they disagreed: `_country_code("Russia")` was `""` and `_country_obj("Russia")` was `{"name": "Russia"}` with no code (pycountry's name is "Russian Federation"), while "Turkey" resolved only in `_country_obj` (pycountry renamed it Türkiye). A mapper that read a jurisdiction, nationality or address country from a name therefore wrote no code for a Russian or Turkish party, and the ISO-keyed FATF, EU high-risk, non-EU and EU tax-list checks passed over it silently — the failure the Phase 239 input contract exists to prevent. The new `bods/countries.py::country_code` is the one reading: the alias table the residence ticket built from 5,500 Companies House values (UK nations, abbreviations, old and common names, misspellings such as "Untied Kingdom" and "Phillipines"), merged with the native-language names `_country_obj` carried (Sverige, Österreich…); then an ISO 3166-2 subdivision → its country; then pycountry. `_country_code`, `_country_obj` and `residence.resolve_country` are thin wrappers and agree on every alias and every ISO name, alpha-2 and alpha-3 (pinned); `_country_obj` keeps pycountry's ISO name, so only codes change. Wikidata's label fallback (a summary cached before P297) goes through it too: a cached Rosneft now exports `{"name": "Russia", "code": "RU"}` — the test that pinned the old name-only answer is updated. The FtM jurisdiction path keeps a subdivision ("US-DE") as its own code before the resolver reduces it, and FtM nationalities use `_country_obj`. Never a stand-in: "Korea", "Channel Islands", "Kosovo" and "New York" stay name-only in every helper. Measured on 4 Nov 2026: in the local cache (4,377 files) the names that gain a code are all Companies House address countries — "Russia" ×9, "Turkey" ×4 (already coded in `_country_obj`, now in `_country_code` too), "The Netherlands" ×3, "Holland", "Hong Kong Sar", "U.K."; the GLEIF and subsidiary subdivisions do not pass through these helpers. On the deployed golden set (all fifteen subjects, including Rosneft, Persia International Bank and Bank Saderat PLC) no country object without a code would gain one — the uncoded values left are Companies House and OpenCorporates demonym nationalities ("British", "Iranian"), which are not country names and are out of scope — so no golden signal is expected to move, and `SIGNAL_RULES` is unchanged (no rule's output changes beyond its input). After deploy, re-run the findings regression and expect no drift.
