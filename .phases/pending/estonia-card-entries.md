Part 2 of the full-history ticket. RIK's `registrikaardid` open-data file holds every entry on every registry card — 2,161,627 entries on 379,829 entities on 16 Oct 2026, each with its card, number, date and entry type — and needs no credentials; for Eesti Energia AS (57 entries) and Bolt Technology OÜ (50) it holds exactly the entries the credentialed SOAP card log returns. The index builder reads it as its sixth file into a `card_entry` table, packed one row per company (as one row per entry it would be the largest table in the file): +52 MB SQLite, +8.5 MB gzipped, measured on the real file. `ariregister.card_entries` reads it back; an index built before the table answers nothing rather than failing, so no schema bump. On the History tab every entry is an administrative row, labelled in English with the register's term, dated as filed. The ticket's suggested rule was taken: when the register's own dated history (the SOAP card and beneficial-owner history) was read, card entries stay in the administrative stream, because the same changes are already notable rows with their before and after; when it was not read — no credentials, or a failure — the status, name and succession entry types (bankruptcy, deletion, restoration, name change, merger, division, transformation) become notable rows, since the card is then the only Estonian history there is. Entry types 9998/9999, which carry no wording (written when the non-profit register moved over in January 2018), say so. The refresh workflow refuses to publish an index with fewer than 1.5 million card entries. After the next index rebuild: open Eesti Energia's History tab and turn on the administrative changes — 57 numbered entries from 31 March 1998.
