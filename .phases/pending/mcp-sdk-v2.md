title: The MCP server runs on the Python SDK v2 and speaks spec 2026-07-28.
readme: The MCP server moved to the official Python SDK v2, so it speaks the stateless 2026-07-28 protocol and still serves older clients.
---
First of three steps on the "Update MCP approaches" ticket (25 Nov 2026), from Anthropic's "Skills over MCP, tasks and more" article: skills over MCP and Tasks both need protocol revision 2026-07-28, so the server moves from `mcp` 1.30 (pinned `<2` since August) to `mcp>=2.3,<3`. The port follows the August spike (PR #88): `FastMCP` becomes `MCPServer`; the transport settings move from the constructor to `streamable_http_app()` in `mcp/__init__.py`; the server now names its version and website. A 2026-07-28 client gets `server/discover` and a one-hour public cache hint on `tools/list` (the spike's 24 hours would hide a new tool for a day); a 2025-11-25 client still connects through the old `initialize` handshake. `/.well-known/mcp.json` lists both revisions. The findings regression's MCP caller uses the v2 `Client`. Tests: `mcp.call_tool` returns a `CallToolResult`, and model fields are snake_case. The 307 workaround and the lifespan entry in `app.py` are unchanged, as the spike found.
