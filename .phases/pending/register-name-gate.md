title: The register adapters share one company-name check.
readme: Nine register adapters now check a register's company name against GLEIF's with one shared function instead of nine copies.
tests: backend +9
---
Found by the codebase review of 20 Nov 2026. `acra_singapore`, `cr_hongkong`, `ct_sots`, `dlcp_dc`, `ny_dos` and `sunbiz_florida` each carried a byte-identical `_latin_agree`, `pa_dos` and `rues_colombia` inlined the same four steps, and `opencorporates` had a tenth copy as `_names_match`: comparable form, despaced form, distinctive tokens, then `name_similarity` at `NAME_MATCH_THRESHOLD`. They now call `names.register_names_agree(a, b, threshold=NAME_MATCH_THRESHOLD)`, which returns False on an empty name (each adapter still decides beforehand what a missing name means for it, as before). Behaviour is unchanged: every adapter's own tests pass as they were. Left alone on purpose: Romania's 16-character prefix rule, Argentina's token-subset rule and the dense-script keys in Hong Kong and Taiwan, which answer different questions. The adapters' `_NAME_SIMILARITY_THRESHOLD` aliases are gone; `test_name_match_threshold.py` now pins the shared function's default instead, and `tests/test_register_names_agree.py` fails on any module under `sources/` that re-implements the gate (a function calling `org_comparable_name`, `despace` and `name_similarity` together).
