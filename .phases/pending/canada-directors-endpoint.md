title: Canadian corporations' directors are asked for on the path ISED publishes, so CBCA lookups read their directors again.
readme: Corporations Canada lookups read directors again, asked for on the endpoint path ISED's own API spec gives.
tests: backend +1
---
Every Canadian lookup since the index tier went live (9 Nov 2026) recorded "The ISED API did not return the corporation's directors" and the weekly source-health sweep had the source degraded for six weeks; CN Railway (105333) showed no directors during the ISO 5009 spot-checks. It was put down to ISED's sign-in outage, but the record call through the same gateway and key kept working. The cause was ours: the adapter asked for `/v2/corporations/{n}/directors.json?lang=eng`, copying the v1 record endpoint's shape, while ISED's published spec (`api.ised-isde.canada.ca/swagger/spec/corporations-en.json`) gives `/v2/corporations/{number}/directors` with an integer number and the language as an `Accept-Language` header, and the gateway answered HTTP 500. `directors_url()` now builds the spec's path and the call sends `Accept-Language: en`; a test pins the path, the empty query and the header. Nothing else moves: a failed read is still never cached, so production recovers on the next lookup. After deploy, check a fresh CBCA lookup (`/lookup-register?scheme=CA-CC&id=105333&refresh=true`) has directors, no `source_read` degradation, and `officialOrganizationalRole` codes from `CA_OOR` on the director interests.
