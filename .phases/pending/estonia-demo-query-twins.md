Closes the Notion ticket "Estonia Neo4j demo queries don't return their stated expected numbers" (16 Oct 2026). Its first two items were already done by the time it was worked: the 19 Oct rebuild (Phase 383) rewrote every query the ticket flagged — the join and the BO coverage filter on `EE-ARIREGISTER` and `beneficialOwnershipOrControl = true` (the July query matched any `CONTROLS` edge from a person, hence 3,333), reporting exceptions are read by the bridge party's name (the July export's `:UnspecifiedParty` carried `unspecifiedReason`, never `reason`), the busiest-people query returns `p.name`, and the chain query filters closed records and self-loops — and Phase 404 re-measured the comments against `dataset-estonia-2026-10-25`, whose Neo4j zip ships the file byte-identical. What remained was the third item: `backend/scripts/rdf_demo_queries.py` still asked the July questions (`EE-KMKR`, `XI-LEI-` recordId prefixes, the Kaamos chain) and asserted the July numbers (22,568 joined companies), so the "RDF twin" no longer answered what the Cypher asks. It is rewritten query for query against the current Cypher — the join, BO coverage, natural-person exceptions, exceptions by reason, deepest current chains, cross-border consolidation, busiest register people, share kinds and thresholds, former founders — with every `expect=` set to the Cypher comment's figure, plus the two RDF-only queries (licence per statement, named-graph provenance of the TOFTAN chain's edge) and the 3-hop benchmark for the parked AuraDB question. Two things the twin had to say explicitly: a Neo4j `OWNS` / `CONTROLS` / `MANAGES` edge is one *interest*, so the SQL counts interest nodes through bods-neo4j's family table (`rightsToProfitOrIncome` is `OWNS`, which is why OWNS is 81,910 and not the 81,905 shareholdings), and the Cypher's cross-border comparison drops the 11,922 reporting-exception bridges with no jurisdiction by null semantics, so the SQL joins both jurisdictions. Every figure was also reproduced independently from the JSONL in plain Python before the SQL was written. `docs/datasets.md` now lists `dataset-estonia-2026-10-25` as the Estonia dataset (348,794 statements) and names the Cypher and its RDF twin. No runtime code changed; nothing to check in production. When the dataset is next re-issued, re-measure the Cypher in Neo4j and change the `expect=` values in the same commit.
