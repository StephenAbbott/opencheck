---
title: A post tagged OpenCheck on Medium now reaches opencheck.world/blog by itself, within a day.
readme: A daily workflow imports new OpenCheck-tagged Medium posts onto the blog from Medium's RSS feed.
---
`import_medium.py --feed` reads Medium's author RSS feed (the latest ten posts, in full) into the same shape as an export post and writes every post tagged `opencheck` that `data/blog/posts/` does not hold, matched on `medium_id`; a held post is never rewritten, so a correction made here survives. The feed body opens in three ways and each is read: an all-italic subtitle paragraph (links inside it kept), a figure then that paragraph, or an `<h3>` restating the title, where the first paragraph is Medium's subtitle. Tracking pixels are dropped and CDN images keyed by id as the export's are. Compared with the zip imports of the five OpenCheck posts in the feed on 20 Nov 2026, the only differences are inline code (the feed sends it as plain text), the published time's milliseconds and topic order. `.github/workflows/import-medium-feed.yml` runs it daily at 06:17 UTC (and by hand), runs the blog tests on what it wrote, and commits to `main` with `[skip ci]`, the second workflow that pushes (`contents: write` on its job, the default token), chosen by Stephen over a pull request for the steward. `tests/test_import_medium_feed.py` (4 tests, offline fixture) skips without the importer's converters, so `tests.yml` runs it in its own step with them. After merge, run the workflow once by hand: the five feed posts are already held, so it should write nothing.
