From the Notion ticket "Check out relate from Neo4J" (step 3). `bods/neo4j.py` used to MERGE one `OWNS_OR_CONTROLS` edge per pair of nodes, so when two sources described the same holding the edge kept whichever came last, and nothing on it said which source, whether it had ended, or that a GLEIF Level 2 edge is accounting consolidation. Each relationship statement is now its own edge, MERGEd on its `statementId`, carrying `sourceId`, `source`, `license`, the canvas `category`, the interest types, the share of the holding interest (both ends of a band, v0.4 exclusive bounds as numbers), the BODS beneficial-ownership flag, an officer position, `startDate`, `ended` / `endDate` judged on `endedAsOf` (a saved report's run day on `GET /export`), `undated`, and `notOwnership` + `basis` for the sources integrated ownership leaves out (GLEIF, Open Ownership's GLEIF extract, MEIP — pinned equal to `integrated_ownership.EXCLUDED_SOURCES`). Nodes carry their source and licence. Edge MATCHes are labelled, so each is an index seek, and the script uses core Cypher only: it loaded and queried as written on Neo4j 5.26 without APOC and on Relate 1.2.0 (the guardrail queries in the skill reference included); the three `CREATE INDEX` lines are Neo4j syntax, and the header says to drop them on Memgraph. The property list is in the data dictionary ("Cypher edge properties"). The due-diligence skill gains `references/graph-queries.md`: how to load an OpenCheck export or a bulk dataset into Neo4j, Memgraph or Relate (the bulk zips' `import.cypher` needs APOC; `bods-neo4j to-cypher` rebuilds it without), Relate's default telemetry, and the `WHERE` clauses an ownership query needs (current only, not consolidation, not officers, never summed across sources or across one statement's interests, bands kept as bands, unspecified parties counted not joined, names never joined on, bounded paths). After deploy, export a FullCheck network with two sources on one holding and check it draws two edges.
