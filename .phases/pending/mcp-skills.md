Second of three steps on the "Update MCP approaches" ticket (25 Nov 2026), from Anthropic's "Skills over MCP, tasks and more" article. The handshake instructions name the tools and their order; three skills, `opencheck-due-diligence`, `reading-opencheck-results` and `opencheck-ownership-questions`, carry the longer rules a client should apply before it reports (degraded sources mean incomplete, context is never a finding, a name match is not an identity, figures are per source and never added, GLEIF Level 2 is consolidation, pass on licences). They are served by the `io.modelcontextprotocol/skills` extension (SEP-2640) in `mcp/skills/__init__.py`: `skills/list` and `skills/get` on 2026-07-28 with a manifest of every file's SHA-256 and size, and each file as a `skill://` resource, so a 2025-11-25 client still sees them. The files are read once at import; `tests/test_mcp_skills.py` checks through the protocol that the digests match the served bytes, that every tool a skill names exists and that the directory names match the frontmatter. The handshake instructions gain one line naming the skills; `/.well-known/mcp.json` lists them.
