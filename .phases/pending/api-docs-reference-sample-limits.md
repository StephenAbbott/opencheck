Items 1 to 3 of the Notion ticket "Improve OpenCheck API documentation" (Stephen, 25 Nov 2026), from a review of API documentation practice against the page. The server already served Swagger UI (`/docs`), ReDoc (`/redoc`), `openapi.json` and `llms.txt`; the page linked none of the first three. A Reference block now links all four. Sample data: `frontend/public/api-samples/lookup-taqa-bratani.json` is a recorded production `/lookup` answer for TAQA BRATANI LIMITED, built by `backend/scripts/build_api_sample.py`, which keeps the answer as returned but removes every record from a source whose licence is not free to redistribute (`licensing` colour other than green: OpenSanctions, EveryPolitician, OpenCorporates, OpenAleph and the other conditional licences) — their hits, statements, relationships naming those statements, signals whose evidence compares them, and subject-profile fields they alone state — and writes a `_sample` block naming what was removed and the licences of what is left. The page explains twelve top-level keys and links the data dictionary and the published datasets. Limits and errors: the three request tiers with their numbers, the shared lookup budget, the free 15-minute replay, the rate-limit headers, the `{"detail": …}` error body, the eight status codes the API answers with, and that a 200 with `degraded_sources` is incomplete, not clean. The facts live in `frontend/src/lib/apiReference.ts`; `backend/tests/test_api_reference.py` parses it and fails when a tier disagrees with `config.py`, a route named under a tier is limited differently, the replay window moves, a described key is not a `LookupResponse` field, or the sample loses a key or carries a restricted source. `llms.txt` names the sample and the limits section. API versioning was left out on purpose (Stephen: very few API users yet), and so was a PDF of the docs. Rebuild the sample with the script when the response shape changes.
