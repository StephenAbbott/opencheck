From the OO usable-data check (opportunity 3; OO feature 8, *clear field and object descriptions*). OpenCheck documented its inputs and concepts (dates, identifiers, risk signals, how it works) and OpenAPI covered request parameters, but nothing described the output field by field. `opencheck/data_dictionary.py` now renders `docs/data-dictionary.md` from the code: the Pydantic response models' fields with the `#:` comment or `Field(description=)` beside each (read with `ast`), the `RiskSignal` / `DegradedSource` dataclasses and their closed vocabularies (reasons, checks, kind, confidence), the BODS extension registry (`EXTENSIONS`: `opencheckSourceId`, `opencheckOfficerPosition`, `gleifLegalEntityEvent`, each with where it sits, an example and the phase that introduced it), the annotation motivations and helpers, the export tables — bods-gql's node/edge dataclasses for CSV / Excel / BigQuery, the batch `rows.csv` columns, and the Senzing, FollowTheMoney and AML AI row keys observed by running the real writers over a synthetic sample bundle — and the MCP tools with the top-level keys of the dict each returns, harvested from the tool bodies one hop into `mcp/shaping.py` and `owners.py`. Three rules keep it honest: a column or key the writers produce with no entry in `COLUMN_DESCRIPTIONS` is an error, not a blank row; a mapper that yields a statement carrying an unregistered `opencheck*` key fails the conftest guard, and a string literal of that shape anywhere in the package fails `test_data_dictionary.py`; and the committed file must equal the rendering (`scripts/generate_data_dictionary.py --check`, a step in the drift-checks workflow beside the OKF check). The core response models (`LookupResponse`, `ReportResponse`, `RegisterLookupResponse`, `SourceHit`, `SourceInfo`, `DeepenResponse`, `LookupSourceResponse`, `SearchResponse`, `RiskSignal`, `DegradedSource`, `CrossSourceLink`, `PossiblySame`) are in `STRICT_MODELS` — every field must carry a description, and the ones that had none gained `#:` comments in the source; the other routers' models render with whatever comments they have and join the strict set as they are documented. The CSV, BigQuery and AML AI zips now carry a `DATA-DICTIONARY.md` rendered from the same descriptions, `LICENSES.md` in every export links the page, and the README's docs table lists it.
