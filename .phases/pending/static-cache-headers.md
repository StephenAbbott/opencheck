Step 4 of the "Speed up first load of the opencheck.world homepage" ticket. Render Edge Caching ("Common static files") was switched on on 31 Oct 2026, and it keeps only what `Cache-Control` allows. `app.py`'s `spa_fallback` sent `no-cache` for every file outside `assets/`, so the logos, the New features illustrations, the graph's flags and BOVS icons were fetched from the origin on every visit. `opencheck/static_cache.py` now holds the rule (`spa_cache_control`): hashed `assets/*` a year and immutable, as before; the HTML shell, `version.json` (Phase 331's deploy check), `robots.txt` and `sitemap.xml` `no-cache`; everything else `public, max-age=3600, stale-while-revalidate=86400` — they change only with a deploy, and a deploy purges the edge. And the reverse risk: `GET /export` (16 response shapes) and `GET /batch-export` set no `Cache-Control`, and a header-less GET answer is one Render's edge may hold for two hours. `DownloadNoStoreMiddleware` (pure ASGI) marks any response with `Content-Disposition: attachment` and no `Cache-Control` of its own as `no-store`; a route that sets its own header keeps it. Production had answered `/export` `DYNAMIC` on 31 Oct (the URL has no file extension); this makes it explicit rather than a property of the URL. The footer's GODIN logo was the homepage's one remaining third-party request (godin.gleif.org, a DNS and TLS round trip on every cold visit); it is now `frontend/public/godin-logo.png` (GODIN's file, unchanged) with its dimensions and `loading="lazy"`. The New features illustrations already had dimensions and `loading="lazy"`, and GoatCounter already loads async — no change. CLAUDE.md's Deployment section said the frontend is served separately; it is served by `opencheck-api` since Phase 88, and the section now says so, names Render's edge and how the headers govern it, and points at `measure-cold-load.mjs`. After deploy: `curl -sI https://opencheck.world/godin-logo.png` twice shows `HIT` on the second; `/export?lei=…` shows `cache-control: no-store`.
