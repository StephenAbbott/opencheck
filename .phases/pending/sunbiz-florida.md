The new `sunbiz_florida` adapter is dispatched on GLEIF RA000603 (12,885 LEIs, 3,079 ISSUED) and reads a SQLite index built from the Division's quarterly `cordata.zip` (12,987,601 fixed-width records, every record on file) and `corevent.zip` (15,083,889 events), downloaded from its public SFTP server. The index keeps every active record and every record an LEI names — by document number, or by FEI where the LEI filed an EIN — 3,821,336 records on the October 2026 files (a full parse found none malformed). It is built quarterly by `refresh-sunbiz-florida-index.yml` (`refresh_sunbiz_florida_index.sh` by hand if a runner cannot reach port 22), published as the `sunbiz-florida-index` release asset and downloaded at boot onto the persistent disk. Stephen's decisions (D1–D9 on the Notion ticket): every officer title, LLC members included, is `seniorManagingOfficial`, never an owner; officers and the registered agent carry name, city and state only, never a street or ZIP; the agent is not a party; the FEI is asserted as `US-EIN`; a merger or conversion partner is named, never related; status `I` is dated by the latest dissolution, revocation, withdrawal or merger event not undone by a reinstatement, and a foreign filing's `I` only ends its authority in Florida. GLEIF's name is checked against the current and every event-recorded name; a recorded rename with no matching name passes with an annotation (the events file carries each name after a change, never the formation name), and anything else is a note card. General partnerships, LLPs and the daily files are follow-ups.
