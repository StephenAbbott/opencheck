The first run of `refresh-sunbiz-florida-index.yml` (31 Oct 2026) reached the Division's SFTP server from a GitHub runner, which had been untested (cordata.zip, 1.79 GB, in 422 s; corevent.zip in 46 s). It then failed: `gleif_registered_as` filtered on `TRANSFERRED`, which GLEIF answers with HTTP 400 ("Invalid enum value"), as it does `CANCELLED`. The builder now asks for the eight values GLEIF's enum holds (`GLEIF_REGISTRATION_STATUSES`). It also refuses to build when the per-status totals do not add up to the unfiltered total, so a status GLEIF adds later cannot silently drop records. Read live on 31 Oct 2026: 12,891 records under RA000603, the eight statuses sum to it, and they give 12,871 document numbers and 5 FEIs. Run from this branch, the workflow published the first index: 3,821,344 records (12,822 named by an LEI, cut 7 Oct 2026), 1.9 GB (690 MB gzipped), larger than the 1.2 GB estimated. The first production lookups found three readings to fix. (1) A record's "last transaction" date leaves out annual reports (D.D.A. CORPORATION: 2003, with a 2026 report), so a company is now dated by the later of the two. (2) Revocation events (`CORAMREVAR` …) end a domestic limited partnership's certificate as well as a foreign filing's authority, so they now read "revoked", not "authority revoked". (3) The state/country code `OC` is the layout's "other country": it stays without a jurisdiction and is now said in words in `entityType.details`. Check after merge: re-run the workflow by hand, and confirm the `sunbiz-florida-index` asset is published and a Florida LEI shows the card once Render has downloaded it.
