title: The MCP export answers with a link to the run, not the whole graph.

From Anthropic's "Code execution with MCP" (Notion ticket "Update MCP approaches", Stephen's go-ahead of 26 Nov 2026): a large tool result passes through the model's context whole, and `opencheck_export_bods` returned every statement of a group's graph inline — thousands of statements with `include_subsidiaries`. By default (`delivery="link"`) it now returns `statement_count`, `statement_counts` by record type, the integrated-ownership and disclosure blocks, the licence notices and a `download_url` to `GET /export` naming the held run (`run=<run_completed_at>`). `/export` gained `run`: it serves exactly that run while the replay cache holds it (15 minutes, `link_expires_at`) and answers 409 otherwise, never starting a fresh check, so a link costs no lookup and can never serve a different run from the one counted. `delivery="inline"` keeps the old answer, narrowed by `record_types` and cut at `max_statements` (default 200, at most 5,000) with `total` / `truncated`. The ownership-questions skill, `docs/mcp-server.md` (new "Export by link" section) and the /api MCP table say so. Measured at the same time: the fifteen tool definitions come to about 6,700 tokens, so progressive tool loading or a `search_tools` tool was not built. After deploy, call the tool from Claude on a large group (Shell with `include_subsidiaries`) and fetch the link once inside and once after the window.
