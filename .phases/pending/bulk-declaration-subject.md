Follow-up to the declaration-subject phase (Phase 396; Notion "Stamp declarationSubject in the bulk build scripts"). Phase 396 stamped `declarationSubject` only on the lookup paths, so the statements the bulk scripts mapped kept the factory default, in which every entity and person names itself — the next Estonia dataset would have shipped that shape on every non-subject party. `scripts/sweep_estonia.py` now stamps each GLEIF and register bundle as its own network (`stamp_bundle`, the lookup's rule: `ref=lei` for GLEIF, `hit_id=code` for the register) and records each bundle's subject in `gleif-subjects.txt` / `register-subjects.txt`. A release file holds many networks and one record per party, so a person on two boards or a company that is its own subject and a shareholder of others sits in several networks; BODS's Record identifiers guidance would give such a party one record per network. Stephen's decision (25 Oct 2026): keep one record, so the party stays one node across companies, and name one network — a relationship keeps its bundle's subject, a network's subject names itself, and any other party names the lowest `recordId` among the networks whose relationships reference it, a rule independent of build order (`bods/declaration.py`: `relationship_networks`, `settle_party`, `settle_shared_parties`, `declaration_problem`, `release_declaration_problems`; `network_subjects` factored out of `stamp_merged`). `assemble` settles parties in a streaming second pass, and `check` refuses a statement naming no recorded network, a subject naming another network, or a party naming a network none of its relationships belong to; both refuse a work directory without the subject files, because the pre-phase shape satisfies any rule read back from the file itself. The manifest gains `network_subjects`, `parties_settled_to_one_network` and a note. `scripts/build_laundromat_dataset.py` re-stamps each subject's raw with `stamp_merged` (idempotent; raws cached before Phase 396 carried the factory default), collects the networks with `network_subjects`, settles shared parties and counts breaches as `declaration_subject_problems` in the manifest and release notes rather than refusing — its subjects are real lookups, and a source a lookup could not resolve keeps the default there too. `scripts/map_psc_stream.py` (the offline PSC harness) stamps each event as its company's network. Left alone on purpose: `extract_bods_subgraphs.py` republishes Open Ownership's statements, whose declarations are OO's; `export_rdf_bulk.py` maps nothing; the diagnostic scripts publish nothing. `docs/identifiers.md` gains a "Release files" section. After merge: re-issue the Estonia dataset (`sweep_estonia.py --stage all`, then `check`) from main.
