---
title: Phase numbers are assigned at merge, by a workflow on main.
readme: Phase numbers and the status row are now written when a pull request merges, so branches in flight no longer collide on the number or conflict on the stamped files.
tests: backend +49
---
Every branch used to claim its own phase number off whatever `main` it could see and edit the same three files at the same spot — the end of the table in `docs/status.md`, the README's Latest line and the regenerated `statusMarkdown.json` — so with one chat per Notion ticket, two branches in flight at once claimed the same number (154, then 164 twice, in September 2026) and every second pull request conflicted even when the code did not; the two-commit never-rebase rule existed only to protect the row's hash citation through that. The stamp now moves to the moment the work lands: a branch adds one changeset under `.phases/pending/` (title, README sentence, optional test-count deltas, the narrative) and touches none of the three files; `.github/workflows/stamp-phase.yml` runs `backend/scripts/stamp_phase.py --apply` on every push to `main` that carries one, which takes the next number from the highest row, appends the row citing the first-parent commit that landed the changeset, bumps the spelled-out count, applies the deltas to the footer, rewrites the Latest line, regenerates the JSON, deletes the changeset and commits back with `[skip ci]`. Several changesets in one push are numbered in the order they landed; the job checks out the tip of `main`, not the pushed sha, and restarts from the tip if its push is rejected, so a queued run cannot hand out a number the run before it used. On a pull request the same script runs `--check`, which validates the changeset and refuses a branch that both adds one and hand-edits the stamped files; a hand-stamped branch with no changeset is still accepted during the transition. The script asserts the CLAUDE.md table rules after every change (three blank lines, rows contiguous, no number twice, the last row the highest, the intro count matching it, and a citation on every row it writes — about seventy-five hand-written rows never carried one, so that rule is not asserted on the file as found), so a broken table fails the workflow instead of reaching `main`. CLAUDE.md's status-file section now opens with the new rule and a "Branches and pull requests" section replaces the claim-a-number instructions; branches are named for the work (`feat/<slug>`), never for a number. This phase is the first stamped by the workflow — its own changeset is the test.
