The OCP Data Registry copy behind the MTender source stopped at 3 March 2026. `opencheck/mtender_harvest.py` and `scripts/harvest_mtender.py` read MTender's public API forward from a cursor: the listing (`/tenders/?offset=`, 100 procedures a page by latest update, `{}` once caught up) names what changed, and each procedure's package is read whole and flattened into the registry's merged release shape, because MTender puts awards on the evaluation and negotiation stage records and the title, method and buyer on the procedure's own record. Only active awards, their suppliers and the buyer are kept; a party's contact point and address are never read into the store, and a procedure with no active award is dropped from it. The store (`mtender_harvest.jsonl.gz` plus a state file holding the cursor) lives on the `mtender-harvest` release and is fetched, extended and replaced by the weekly `refresh-mtender-index` workflow before the index is built; the cursor moves only past a page read whole, and the run stops inside a time budget, so a first run, which starts about a year back (the API answers an older offset with an empty body), backfills across several runs. `build_mtender_index.py --harvest` merges the two inputs, the harvest's reading of a procedure winning, and the snapshot's cut is now the harvest cursor. At four requests at a time the API answers 10 to 15 packages a second; a year is about 200,000 procedures and 25 to 40 MB gzipped in the store, while the index stays about 5 MB. After merge, dispatch the workflow by hand until its summary says the harvest is caught up.
